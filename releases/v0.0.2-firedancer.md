# Release Notes

## Release: [M0: The Trust Foundation](https://github.com/deeprnd/tickoni/milestone/13)

M0 closes in this release.

Its two epics now ship together:

* [V0.0: Proof Of Correctness](../epics/v0.0.md)
* [V0.37: Firedancer Integration](../epics/v0.37.md)

V0.0 established the deterministic event path: synthetic financial events can be framed, normalized, deduplicated, policy-checked, audited, replayed, and inspected without external effects.

V0.37 hardens the boundary around that proof: Tickoni now builds and tests against the Firedancer substrate it actually reuses, exposes Tickoni-owned product topologies, and keeps Solana validator concepts out of the Tickoni runtime surface.

```text
V0.0: prove the deterministic event path
-> V0.37: harden the Firedancer boundary around it
-> M0: trust foundation closed
```

The operator now has a product-owned runtime foundation instead of a proof sitting too close to borrowed validator structure. This release still does not run agents, call models, connect to brokers, databases, or payment networks, move money, or place trades. It closes the trust foundation milestone those later flows must stand on.

## Headline Features

### 1. M0 Closes With Exactly Two Epics

M0 now has its full intended shape:

* `V0.0` delivered the deterministic runtime proof,
* and `V0.37` delivered the Firedancer integration boundary that makes that proof product-owned.

There are no additional hidden M0 epics. The milestone closes here.

### 2. Standalone Firedancer Substrate Build

Tickoni now has a cleaner build contract with its reused C substrate.

`just build-fd` builds the Firedancer libraries Tickoni actually reuses:

* `fd_tango`,
* `fd_util`,
* `fd_ballet`,
* `fd_disco`,
* and `fd_waltz`.

That build path excludes the validator product surface: Solana validator tiles, RPC schemas, unrelated binaries, and other non-Tickoni artifacts do not define the Tickoni build story.

`just build-tk` then builds the Zig `tickoni-supervisor` against that substrate through Tickoni-owned wrappers.

### 3. Tickoni-Owned Product Topology

Tickoni's product topology is now explicit about being Tickoni's.

The product runtime registers Tickoni tile IDs such as:

* `tkings`,
* `tknorm`,
* `tkdedu`,
* `tkpoly`,
* `tkaudt`,
* `tkrepl`,
* `tkmetr`,
* and `tkdiag`.

The declared investment workflow likewise uses Tickoni tile IDs such as `tkcase`, `tkdisp`, `tkagnt`, `tkmodl`, `tktool`, and `tkadpt`.

Validator tile identities are no longer the conceptual frame for the product runtime. Firedancer remains the infrastructure substrate, not the product vocabulary.

### 4. Boundary Verification In Build And Test

V0.37 adds evidence that the Firedancer boundary is real and maintained, not just described in docs.

The repository now has build and test lanes that verify the integration surface:

* `just build-fd`,
* `just build-tk`,
* `just test-unit-tk`,
* and `just test-integration-tk`.

Those lanes exercise the product topology, Firedancer-backed link and workspace plumbing, and Tickoni-owned runtime wrappers without making Solana validator semantics part of the product contract.

### 5. Documentation And Boundary Clarity

The architecture, topology, build, and testing docs now tell the same story:

* Firedancer is the systems substrate,
* Tickoni is the product runtime,
* Solana validator semantics are excluded from Tickoni's product surface,
* and the active Tickoni runtime lives under `src/app/tickoni/` and `src/tickoni/`.

This release is as much about precision of identity as about build output.

## Governance and Safety

### 1. The Runtime Boundary Is Explicit

Tickoni now draws a clearer line between inherited substrate and owned product behavior.

Firedancer contributes queues, topology discipline, workspaces, lifecycle, metrics, diagnostics, and related systems primitives. Tickoni owns the product topology, tile identities, financial semantics, and runtime surface.

That separation reduces ambiguity for operators, reviewers, and later feature work.

### 2. Product Topology Does Not Inherit Validator Semantics

This release keeps Solana validator concepts out of Tickoni's product runtime shape.

The product topology is described in Tickoni tile IDs and Tickoni docs. Validator tile names and validator-only flows are not presented as the product runtime.

### 3. External Effects Still Stay Disabled

Closing M0 does not change the no-side-effects rule established by V0.0.

There is still no live model provider call, broker call, payment call, approved execution ledger mutation, trade placement, or money movement in this release.

V0.37 hardens the foundation. It does not widen authority.

### 4. Fail-Closed Integration Matters

Build isolation and topology clarity are not cosmetic.

They reduce the chance that Tickoni accidentally inherits unrelated protocol assumptions, toolchain requirements, or product semantics from the validator codebase it borrows infrastructure from.

## Platform Work

### 1. `tickoni_fd` Build Scope

The Firedancer-side build is now explicitly scoped to what Tickoni reuses.

That scope narrows the C dependency surface and gives CI and developers a repo-facing contract that matches the product boundary.

### 2. Separate Build Recipes For Substrate And Product

The repo-facing command surface now clearly separates:

* `just build-fd` for the reused Firedancer substrate,
* and `just build-tk` for the Tickoni runtime.

That makes it easier to reason about which layer changed, failed, or needs review.

### 3. Topology Definitions Live In Tickoni-Owned Code

The active product topologies are declared in `src/app/tickoni/topologies.zig`, not inferred from validator registration tables.

That keeps product identity and runtime wiring in the part of the tree Tickoni owns.
